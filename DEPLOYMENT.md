# Render Production Deployment Guide — Swasthya

This guide provides step-by-step instructions for deploying Swasthya to [Render](https://render.com) using Blueprint (`render.yaml`) or manual web service creation.

---

## 1. Architecture Summary

- **Runtime**: Node.js 18 or newer
- **Host Binding**: `0.0.0.0`
- **Port**: Dynamically supplied by Render via `process.env.PORT` (defaults to `4173` locally)
- **Health Check Endpoint**: `/api/health`
- **Build Command**: `npm install`
- **Start Command**: `npm start`
- **Static Assets**: Root `index.html`, `manifest.json`, `service-worker.js`, `OneSignalSDKWorker.js`

---

## 2. Deploy Using Blueprint (`render.yaml`)

The repository includes a ready-to-deploy [`render.yaml`](file:///c:/Users/HP/Downloads/VINCERE/render.yaml) specification.

1. Push your repository to GitHub / GitLab:
   ```bash
   git init
   git add .
   git commit -m "feat: complete production integration for Swasthya"
   git branch -M main
   git remote add origin https://github.com/YOUR_USERNAME/YOUR_REPOSITORY.git
   git push -u origin main
   ```
2. Log in to your [Render Dashboard](https://dashboard.render.com).
3. Click **New +** -> **Blueprint**.
4. Connect your GitHub repository.
5. Render reads `render.yaml` and prepares the `swasthya-health-assistant` Web Service.
6. Enter the required environment variable values prompted by Render (see Section 3).
7. Click **Apply**.

## 3. Environment Variables Configuration

Configure these environment variables in your Render Web Service dashboard under **Environment**:

| Variable Name | Required | Description | Example / Location |
| :--- | :---: | :--- | :--- |
| `NODE_ENV` | Yes | Node runtime environment | `production` |
| `HOST` | Yes | Server binding host | `0.0.0.0` |
| `TOKEN_SECRET` | Yes | 64-character secret for HMAC tokens | Auto-generated by Render or `crypto.randomBytes(32).toString('hex')` |
| `SUPABASE_URL` | Yes | Supabase Project URL | `https://xxxx.supabase.co` |
| `SUPABASE_ANON_KEY` | Yes | Supabase Public / Anon API Key | `eyJhbGciOi...` (Safe for client) |
| `SUPABASE_SERVICE_ROLE_KEY` | Yes | Supabase Service Role Secret Key | `eyJhbGciOi...` (**Server only**, never frontend) |
| `CLOUDINARY_CLOUD_NAME` | Yes | Cloudinary account cloud name | Found in Cloudinary dashboard |
| `CLOUDINARY_API_KEY` | Yes | Cloudinary Public API Key | Found in Cloudinary dashboard |
| `CLOUDINARY_API_SECRET` | Yes | Cloudinary API Secret | Found in Cloudinary dashboard (**Server only**) |
| `ONESIGNAL_APP_ID` | Yes | OneSignal Web Push App ID | Found in OneSignal Settings -> Keys & IDs |
| `ONESIGNAL_REST_API_KEY` | Yes | OneSignal REST API Key | Found in OneSignal Settings -> Keys & IDs (**Server only**) |
| `OPENAI_API_KEY` | Yes | OpenAI API Secret Key | Found in platform.openai.com (**Server only**) |
| `OPENAI_MODEL` | No | OpenAI Model ID | `gpt-4o-mini` (default) or `gpt-3.5-turbo` |

## 4. OneSignal Web Push Domain Setup

To enable web push notifications even when the browser tab is closed:
1. In the OneSignal Dashboard, go to **Settings -> Web Configuration**.
2. Set your **Site URL** to your Render production URL (e.g. `https://swasthya-health-assistant.onrender.com`).
3. Ensure HTTPS is active (Render provides automatic TLS/SSL certificates).
4. Verify that `OneSignalSDKWorker.js` is served from the root domain.

---

## 5. Post-Deployment Verification Checklist

Once the build is complete and the service is live:

1. **Verify Health Endpoint**:
   ```bash
   curl https://your-app-name.onrender.com/api/health
   ```
   Expected response:
   ```json
   {
     "status": "ok",
     "version": "2.0.0",
     "services": {
       "supabase": true,
       "cloudinary": true,
       "onesignal": true,
       "openai": true
     }
   }
   ```
2. **Verify Frontend Loading**: Open `https://your-app-name.onrender.com` in your browser.
3. **Register New Patient**: Register an account in **Account / UID** and confirm a unique `PT-XXXXXX` UID is issued.
4. **Upload Medicine Photo**: Add a medicine with an image and confirm it is stored in Cloudinary without frontend credential exposure.
5. **Test AI Care Assistant**:
   - Send an inquiry in English and Hindi.
   - Send an emergency symptom query (e.g. *"I have severe chest pain and cannot breathe"*) and confirm immediate emergency intercept.
6. **Verify Doctor Portal**: Sign in as a doctor and confirm only assigned patients are accessible.
